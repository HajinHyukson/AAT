## 2026-05-16

- Added feature-flagged `viza.finance.text.sentiment` resolver for SEC filing text. FinBERT is implemented as one local model implementation under the resolver protocol; the resolver itself is model-agnostic and also exposes `local_finbert_transformers` (real, lazy-imported) and `local_finbert_onnx` (deferred stub) implementations.
- The resolver emits PIT-labeled, rights-labeled, model-versioned per-chunk sentiment observations, section-level aggregates, and tone deltas vs. the prior filing for the same section. Observations are keyed by a 10-field cache_key (filing_accession, section_id, section_text_hash, parser_version, chunking_policy_hash, model_id, model_version, model_hash, tokenizer_hash, inference_config_hash) that prevents silent model/parser/chunking upgrades.
- Added a pin-1 hash specification with byte-level definitions for `model_hash` (SHA256 of weights file), `tokenizer_hash` (SHA256 over UNIT-SEPARATOR-joined tokenizer files), `chunking_policy_hash` (SHA256 of canonical-JSON of an enumerated policy dict), and `inference_config_hash` (SHA256 of canonical-JSON of an enumerated inference config). Key-set mismatch raises ValueError at compute time.
- Added a pin-2 keyword/regex human-review pre-filter (`HUMAN_REVIEW_TERM_SET_VERSION="v1"`) that runs upstream of inference. FinBERT cannot reliably distinguish "going concern" boilerplate from forward-looking discussion; severe-negative/fraud/legal/short-relevant detection therefore uses an explicit, versioned, auditable term list.
- Added a pin-3 SEC iXBRL section parser scoped to Risk Factors, MD&A, Market Risk on 10-K/10-Q, and 8-K Items 2.02/7.01/8.01 via the EDGAR header items list. Filings without iXBRL section tags emit `section_unparseable` with a warning rather than running a heuristic regex scraper.
- Added a pin-4 `available_at` precision policy: minute-precise EDGAR `acceptedDateTime` -> `lookahead_risk=low`; day-precision fallback to 21:00 ET -> `lookahead_risk=warning`; missing -> `lookahead_risk=not_backtest_safe` and `live_historical_PIT` mode is blocked.
- Added a pin-5 look-ahead audit gate at `tests/lookahead_audit/test_finbert_observation_pit.py` enforcing three assertions: (A) persisted `available_at` equals filing accepted timestamp, never `retrieved_at`/`inference_at`; (B) `replay_from_stored_observations` with `cutoff_timestamp=T` returns only observations with `available_at <= T`; (C) `live_historical_PIT` with unknown or post-cutoff model release date blocks rather than silently falls back.
- Added a pin-6 dual-lookup observation store: cache hits keyed by the 9-field cache_key composite, replay keyed by `run_id` with parser/model/chunking snapshot recorded on the run record. Cache_key is intentionally non-unique on the table (one cache_key -> N chunk observations).
